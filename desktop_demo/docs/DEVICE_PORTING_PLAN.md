# 从电脑原型迁移到“灵机一动”设备

## 保持不变的业务契约

最终设备版需要保持以下状态名称和事件含义：

| 状态 | 含义 | 灯板反馈 | 舵机反馈 |
|---|---|---|---|
| `idle` | 用户在工位，等待指令 | 绿色呼吸 | 居中 |
| `confirm_save` | 询问是否保存断点 | 蓝色呼吸 | 转向用户 |
| `capture_content` | 等待用户说断点内容 | 蓝色闪烁 | 聆听姿态 |
| `away` | 用户已经离开 | 黄色呼吸 | 休眠姿态 |

核心事件：

- `pre_leave_detected()`：视觉模块检测到用户正在起身。
- `return_detected()`：视觉模块检测到用户重新回到座位。
- `receive_voice(text)`：语音板输出的识别文本。
- `ControllerResponse.speech`：需要交给扬声器播放的内容。
- `hardware_feedback`：灯板和舵机需要执行的动作。

## 电脑端与设备端替换关系

```text
电脑端 Flask 按钮       → 摄像头＋姿态模型
电脑端文字输入          → 麦克风＋语音板 ASR
页面文字回复            → 扬声器 TTS/预制语音
页面反馈名称            → 灯板与舵机驱动
SQLite                  → Flash/NVS/平台知识库
Python Controller       → C++ 状态机（同一状态和事件）
```

## 推荐开发顺序

1. 在电脑端通过全部状态机测试。
2. 固定一份“事件、输入、输出”接口文档。
3. 在灵机一动工程中建立 C++ 状态机，不先接硬件。
4. 接入语音板，将 ASR 文本送入状态机。
5. 接入摄像头和 `.espdl` 姿态模型，产生离座/归来事件。
6. 接入灯板、舵机和扬声器。
7. 用真实桌面机位调节姿态阈值和防抖时间。
8. 截取一次完整平台调用和设备反馈，放进交付说明。

## 完整调用示例

```json
{
  "trigger": "pre_leave_detected",
  "input": "摄像头连续检测到坐姿高度上升",
  "result": {
    "state": "confirm_save",
    "speech": "检测到你准备离开，需要帮你记录当前任务断点吗？"
  },
  "hardware_feedback": {
    "led": "blue_breathe",
    "servo": "look_at_user"
  }
}
```

这个结构可以直接用于“一次完整调用的触发条件、输入、返回结果与设备反馈”说明。
